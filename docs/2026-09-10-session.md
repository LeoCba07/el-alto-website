## What changed

### Videos section on the homepage (`7f35c7b`, `22ecc1d`)

The YouTube work was pulled forward from December, without waiting for the
reshoot. The section sits below Testimonios, on a cream background to keep the
alternation.

- **Content comes from Sanity:** a new singleton, "Videos (Home)"
  (`videosInicio`). Each video has a title, a YouTube link, an upload date and
  an optional description.
- **No hardcoded fallback:** with no videos in Sanity, the section doesn't
  render. That is deliberate, given how much drift the fallback arrays caused.
- **What's loaded today:**
  - "Complejo El Alto desde el aire": `J442JqMr_8g`, uploaded 31 Jan 2026
  - "La naturaleza que rodea Tanti": `HoDUt5H_jkI`, uploaded 24 Jan 2026
- **Unit videos wait:** they go on `/unidades` after December's reshoot, not
  on the homepage.
- **Lite embed:** the page shows the thumbnail, and the `youtube-nocookie`
  player mounts only on click, instead of about 1 MB of player per video on
  page load.
- **Also added:**
  - `VideoObject` structured data
  - `i.ytimg.com` and `youtube-nocookie.com` in the CSP
  - a `video_play` event
  - a "Videos" dot in the section indicator

Two traps found along the way:

- **Missing thumbnails don't error.** Not every video has a `maxresdefault`
  thumbnail. YouTube answers a missing one with a 404 whose body is a valid
  120×90 grey image, so the browser loads it, `onError` never fires, and the
  aerial video's card showed a stretched grey box.

  Checking `naturalWidth` in `onLoad` didn't hold either: `next/image` waits
  on `img.decode()` before calling `onLoad`, and that never resolves in a
  hidden tab. The fix was to move the choice to the server:
  `youtubeThumbnail()` sends a `HEAD` to `maxresdefault` and falls back to
  `hqdefault`, which always exists.
- **Video IDs were first paired with the wrong titles.** When the channel's
  RSS was read by lining up fields in columns, the channel's own title and
  date took the first row, and every ID landed next to the previous video's
  title. "Desde el aire" played the nature video, and the second card was
  Unidad 12. Caught on the preview and fixed in Sanity. Before using a video
  ID, check its title with oEmbed:

  ```bash
  curl -s "https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<ID>&format=json"
  ```

### Hero enquiry bar (`368b81a`, `182eb24`, `0857c31`)

## Sanity access

- **`SANITY_API_TOKEN` in `.env.local` is rejected by this project.** It's
  a non-expiring token, but project `tw1o0dkg` answers `401 Unauthorized`
  (checked twice on 10 Sep, once on a write and once on a read of
  `/users/me`). Tokens are per project, so possible causes:
  - it belongs to a different Sanity project
  - the value in `.env.local` differs from the token in sanity.io/manage
  - it was deleted there

  Keep it in `.env.local` until that's cleared up.
- **`SANITY_API_TOKEN_PREVIEW` works and can write.** It was used to create
  and then patch the `videosInicio` document. It expires after 30 days, around
  10 October 2026.
- **Neither token is used by the site's code.** The site reads Sanity
  without auth, through the CDN, so the preview token expiring breaks nothing
  on the site.
- **The seed and migration scripts in `scripts/` do read `SANITY_API_TOKEN`**
  (not `_PREVIEW`), and the README asks for it too. Until that name holds a
  working token again, those scripts fail with 401. To run one today,
  override the name on the command line:

  ```bash
  SANITY_API_TOKEN=$SANITY_API_TOKEN_PREVIEW node scripts/<script>.mjs
  ```
- **New documents take a few minutes to reach the site.** After the document
  was created, the preview took a few minutes to show it, although the API and
  the CDN already returned it. It wasn't a code problem.

## Testing limits worth knowing

None of today's work has been seen at phone width in a browser.

- **Claude in Chrome** can't shrink the window below desktop width.
- **The app's Browser pane** reports a 0×0 viewport while it's hidden:
  - lazy images never load
  - `img.decode()` never resolves
  - screenshots come back blank
- **Headless Chrome** (`--screenshot`) writes the file but then hangs on exit,
  and it captures before the hero's fade-in animations run.

`.claude/launch.json` (untracked, kept) defines `prod-local`: `next start` on
port 3001, which leaves the usual dev server on 3000 alone.
